# 接口说明（前端对接）

权威契约是 OpenAPI：交互式文档 `/api/v1/docs`，机器可读 `/api/v1/openapi.json`（3.0，给 Apifox 导入）。
每个接口的字段、取值和示例以那里为准；本文讲**通用约定、核心流程和容易踩的坑**。
导入后请用 **Bearer Token**（不是自定义请求头 `access_token`）；可选 Query 不要勾选空值，或勾了空串也会被当成未传。

对外入口：全栈部署时为 `http://localhost:8080`（Nginx）；本机开发模式为 `http://127.0.0.1:8000`。
下文所有路径省略前缀 `/api/v1`。

## 1. 通用约定

- **成功响应直接返回资源**，没有 `{code, msg, data}` 外层包装。
- **列表统一分页**：`items`（当前页数据）、`total`（总数）、`page`、`page_size`。
- **GET 查询参数里的空字符串视为未传**（与缺省相同，不过滤）。`category_id=`、`status=`、
  `page=` 不会 422，会走该参数的默认值。非法值（`category_id=abc`、`status=FOO`）仍 422。
  **JSON 请求体不做此兼容**：body 里 `"category_id": ""` 仍按类型报错；可选条件请省略该字段或传 `null`。
- **错误统一 RFC 9457**（`application/problem+json`），HTTP 状态码不是 200。
  字段：`code`（稳定业务错误码，前端按它分支）、`title`、`detail`、`trace_id`（报障时提供给后端）。
  422 校验失败示例（实测）：

  ```json
  {
    "type": "about:blank",
    "title": "请求参数校验失败",
    "status": 422,
    "code": "REQUEST_VALIDATION",
    "errors": [{"loc": ["body", "acquired_from"], "msg": "Value error, 时间必须携带时区", "type": "value_error"}],
    "trace_id": "01a057a8-40bc-7263-978a-0e2ac457d6a1"
  }
  ```

- **时间一律带时区**（如 `2026-08-31T11:46:48.553807Z`）。提交时间字段时也必须带时区，否则 422。
- **空间范围只接受 EPSG:4326 的 GeoJSON `Polygon` 或 `MultiPolygon`**，字段名 `spatial_geojson`
  （也接受别名 `geometry`）。**没有 bbox 参数**——传 `bbox` 会被静默忽略，不会过滤。
- **本平台这期只收 GeoTIFF**（`.tif` / `.tiff`）。创建上传时必须声明 `kind`（`SATELLITE` 或 `UAV`）
  和 `data_source_id`（产品型号，如哨兵二号）。矢量和附件已下线。

## 2. 登录与令牌

- **除下列匿名接口外，所有业务请求必须带** `Authorization: Bearer <access_token>`。
  无令牌、令牌无效或过期返回 401；已登录但权限不够返回 403。
- 匿名接口：`POST /auth/login`、`POST /auth/refresh`、`GET /healthz`、`GET /readyz`、
  `GET /metrics`（仅内网；Nginx 对外 404）、`GET /tiles/verify`（Nginx 校验瓦片令牌）、
  `GET /docs`、`GET /openapi.json`。
- 先 `POST /auth/login`（用户名或邮箱 + 密码）拿到令牌。访问令牌默认 1 小时有效；
  过期后用 `refresh_token` 调 `POST /auth/refresh` 换新的一对。
- 没有自助注册。本机开发用 `.env` 里的引导管理员登录；之后由 ADMIN 创建账号。
- 角色：`USER` 可上传/管理卫星与无人机、检索、申请瓦片与下载、查看数据源/生态/监测；
  `ADMIN` 额外管理用户、数据源、生态参数与数据源关系、监测计划（含手动触发）以及监测执行回写。

## 3. 核心流程：上传一个文件到地图展示

这是最重要的链路，前端按下面五步走（以一个 48MB 哨兵一号影像实测为例）：

```
① 创建会话 ──► ② 分片直传 MinIO ──► ③ 完成上传 ──► ④ 轮询卫星/无人机详情 ──► ⑤ 申请瓦片/下载地址
```

### ① 创建上传会话

```http
POST /uploads/sessions
Content-Type: application/json

{"file_name": "S1_2025_1_08.tif", "size_bytes": 50001366, "kind": "SATELLITE", "data_source_id": 14}
```

响应（201）：

```json
{
  "session_id": 2,
  "kind": "SATELLITE",
  "record_id": 2,
  "part_urls": [
    {"part_number": 1, "url": "http://localhost:9000/remote-scene/uploads/...?X-Amz-Signature=..."},
    {"part_number": 2, "url": "..."},
    {"part_number": 3, "url": "..."}
  ],
  "expires_in_seconds": 86400
}
```

服务端按 16MiB 一片自动切分，前端不用自己算分片。返回的 `part_urls` 是
**MinIO 预签名 PUT 地址**——文件字节直接传给对象存储，不经过本服务。

### ② 逐片直传

对每个分片，按顺序读文件对应字节段，`PUT` 到对应地址：

```http
PUT {part_urls[n].url}
Content-Length: {这一片的字节数}

<这一片的原始字节>
```

要点：分片按 1..N 顺序上传（S3 Multipart 要求）；不要把整个文件读进内存，
边读边传；地址有有效期（`expires_in_seconds`），过期用补签接口换新地址。

### ③ 完成上传

```http
POST /uploads/sessions/{session_id}/complete
```

返回 `{session_id, kind, record_id}`。此调用幂等——重复调用返回同一结果，不会重复触发处理。
完成后后台自动开始处理：合并分片、校验、生成 COG/缩略图/空间信息。

### ④ 轮询卫星或无人机详情（注意：轮询记录，不是轮询任务）

```http
GET /satellites/{record_id}
GET /uavs/{record_id}
```

看 `status` 字段，直到出现终态：

| status | 含义 | 前端动作 |
| --- | --- | --- |
| `UPLOADING` / `VALIDATING` / `PROCESSING` | 处理中 | 继续轮询 |
| `READY` | 完成 | 读元数据，`has_map`/`has_download` 为 true 时可申请瓦片/下载 |
| `NEEDS_INPUT` | 缺少可人工补充的信息（最典型：文件无坐标系） | 读 `diagnostics`，调 `POST /satellites/{id}/inputs` 或 `/uavs/{id}/inputs` 补充后从断点续跑，**不需要重新上传** |
| `FAILED` | 处理失败 | 读 `diagnostics` 定位原因 |

`READY` 后详情里会带出：`crs`、`band_count`、`bbox`、
`spatial_geojson`（EPSG:4326 覆盖范围，可直接画图）。

### ⑤ 展示与下载

```http
GET /satellites/{id}/tile-url      # 或 /uavs/{id}/tile-url
GET /satellites/{id}/download-url  # 或 /uavs/{id}/download-url
```

两个都是**短期地址**（默认 1 小时过期）。过期后重新申请，不要缓存当永久 URL 用。
瓦片响应里的 `tile_url_template` 形如
`.../tiles/WebMercatorQuad/{z}/{x}/{y}.png?url=...&bidx=1&token=...`，
直接交给前端地图库（Leaflet/MapLibre/OpenLayers 的 XYZ 模板）即可，**不要改主机名、不要自己拼参数**。

> 开发模式注意：`dev.sh` 起的本机进程没有 Nginx，瓦片地址的 `/tiles/` 前缀无人服务。
> 真实联调请用全栈 `docker compose up`（8080 端口，Nginx 校验令牌，无令牌一律拒绝）。

## 4. 断点续传与中止

- 中断后 `GET /uploads/sessions/{id}` 看 `uploaded_parts`（已传）和
  `missing_part_numbers`（缺失），只补传缺失的片。
- 某片地址过期：`GET /uploads/sessions/{id}/parts/{part_number}/url` 补签
  （会话还在 `PENDING` 状态才可用）。
- 放弃这次上传：`POST /uploads/sessions/{id}/abort`，对应记录记为失败。
  已完成的上传不能中止。

## 5. 卫星、无人机与检索

- 管理页用 `GET /satellites`、`GET /uavs`：按名称、产品型号、状态过滤。
- **地图选数用 `POST /data/search`**（空间几何放请求体）。结果每条带 `kind=SATELLITE|UAV`。

  ```json
  {
    "geometry": {"type": "Polygon", "coordinates": [[[111.0, 39.6], [111.5, 39.6], [111.5, 39.9], [111.0, 39.9], [111.0, 39.6]]]},
    "status": "READY",
    "kind": "SATELLITE",
    "data_source_id": 14,
    "ecological_parameter_ids": [5],
    "precision": "00",
    "acquired_from": "2025-01-01T00:00:00Z",
    "acquired_to": "2026-01-01T00:00:00Z",
    "page": 1,
    "page_size": 20
  }
  ```

  按生态细项检索时必须传 `precision`（`00`/`01`）。系统先查细项↔产品型号关系，再过滤卫星/无人机；
  **关系为空则结果为空**。同时传 `data_source_id` 时取交集。

- 删除是硬删除：`DELETE /satellites/{id}` 或 `/uavs/{id}` 立刻删行，对象入队后由清理进程从 MinIO 去掉。不可恢复。
- 改名称/采集时间用 `PATCH`。

## 6. 数据源字典

产品型号（`000114` 哨兵二号、`000201` 无人机多光谱）不是某一景文件。
`GET/POST /data-sources`、`GET/PUT/DELETE /data-sources/{id}`。
编号 `0001xx` 卫星、`0002xx` 无人机。上传时必须选一个已有型号。

## 7. 生态参数与数据源关系

- 生态参数是细项字典（一行一条，没有 parent_id）：
  `GET/POST /ecology/parameters`、`GET /ecology/parameters/{id}`。
  `code` 是四位细项编号（如 `0102`），英文缩写在 `abbrev`（如 `NDVI`）。
  **检索筛选下拉用 `GET /ecology/parameters/tree`**：按大类分组，根节点没有参数 id，
  只有 `children` 里的细项 id 能传给 `ecological_parameter_ids`。
  大类列表：`GET /ecology/majors`。
- 细项与产品型号、精度的关系：`GET/POST/PUT/DELETE /ecology/data-source-mappings`，
  批量建 `POST /ecology/data-source-mappings/batch`。这是监测和按参量检索的依据。
  没有「分类」表，也没有 `/ecology/mappings`。

## 8. 监测计划

- `POST /monitoring/plans` 创建：名称、边界（4326 多边形）、调度、时区、
  `precision`（`00`/`01`）和可选的生态细项列表。
  调度两种写法：`schedule_type=INTERVAL` 时填 ISO 8601 时长（`P1D` 每天、`PT6H` 每 6 小时）；
  `schedule_type=RRULE` 时填 RFC 5545 规则（`FREQ=WEEKLY;BYDAY=MO` 每周一）。
- 到期后系统自动创建执行（run），按"上次成功执行之后新增、空间相交、细项+精度对应的产品型号、
  READY"挑选卫星/无人机并**冻结输入快照**。
- 手动触发：`POST /monitoring/plans/{id}/trigger`（立刻执行一次，不影响原周期）。
- 查执行：`GET /monitoring/plans/{id}/runs`（列表）、`GET /monitoring/runs/{run_id}`（详情）、
  `GET /monitoring/runs/{run_id}/inputs`（这次选用的卫星/无人机快照）。
- 暂停/恢复：`POST /monitoring/plans/{id}/pause`、`/resume`。
- `POST /monitoring/runs/{run_id}/start|succeed|fail` 是执行方回写状态的接缝，
  供计算侧使用，普通前端不用调。

## 9. 任务（Job）

前端一般**不需要**轮询任务接口——轮询卫星/无人机详情就够了。这些是管理/排障用的：

- `GET /jobs/{job_id}`：任务状态 + 完整事件流（每一步处理的时间线）。
- `POST /jobs/{job_id}/cancel`：排队中的立即取消；运行中的返回 `CANCEL_REQUESTED`，
  任务在处理步骤检查点转为 `CANCELLED`。

任务状态参考：`PENDING → QUEUED → RUNNING → SUCCEEDED / FAILED / RETRYING / NEEDS_INPUT / CANCELLED / MISSED`。

## 11. 常见错误码

| code | 场景 | 前端处理 |
| --- | --- | --- |
| `REQUEST_VALIDATION` | 参数校验失败（422） | 按 `errors[].loc` 定位字段提示用户 |
| `ECOLOGICAL_PARAMETER_CODE_CONFLICT` | 细项编号已存在 | 换一个 `code` |
| `ECOLOGICAL_PARAMETER_ABBREV_CONFLICT` | 英文缩写已存在 | 换一个 `abbrev` |
| `AUTH_REQUIRED` / `AUTH_TOKEN_INVALID` / `AUTH_TOKEN_EXPIRED` | 缺少、无效或过期的 Bearer 令牌 | 引导重新登录 |
| `AUTH_FORBIDDEN` | 已登录但角色不够 | 提示无权限 |
| `USER_DISABLED` | 账号已停用 | 提示联系管理员 |
| `UPLOAD_SESSION_NOT_PENDING` | 会话已不在上传中还想补签地址 | 刷新会话状态 |
| `TEMP_STORAGE_INSUFFICIENT` | 服务端临时盘不足 | 稍后重试或联系运维 |
| `INTERNAL_ERROR` | 服务端异常（500） | 携带 `trace_id` 报障 |

## 12. 排障建议

- 任何错误响应里都有 `trace_id`，报障时提供给后端即可在结构化日志中定位整个链路。
- 上传后长期停在处理中：先看 `GET /readyz` 是否全部 ok，再 `GET /jobs/{id}` 看卡在哪一步。
- 瓦片 401/404：令牌过期就重新申请；确认走的是全栈 Nginx 入口（8080）而不是直连内部端口。
