```

          │

PostgreSQL + PostGIS
   │
   ├── Job + Outbox（同一事务）
   │            │
   │            ▼
   │      Outbox Dispatcher
   │            │
   │            ▼
   │        RabbitMQ
   │            │
   │            ▼
   │      Celery Geo Worker
   │      GDAL/Rasterio/Shapely
   │
   └── 独立 Scheduler
                │
                └── 创建周期 Job + Outbox

MinIO
├── 原始对象
├── COG
├── 缩略图
```

采用两个主要镜像：

- 轻量 API 镜像：FastAPI、SQLAlchemy、Pydantic，不安装 GDAL。
- Geo Worker 镜像：Celery、GDAL、Rasterio、Shapely、PyProj、NumPy。

首版在 Windows Docker Desktop/WSL2 上使用单机 Docker Compose，仅本机开发使用。

## 核心数据模型

资产采用“公共主表 + 版本 + 类型扩展表”：

- `data_asset`：逻辑资产、名称、来源、业务目录、当前版本。
- `asset_version`：不可变文件版本、状态、时间与空间元数据。
- `asset_artifact`：原文件、COG、缩略图和计算成果。
- `raster_asset_version`：CRS、宽高、波段、分辨率、NoData、footprint。
- `vector_asset_version`：几何类型、要素数、属性结构。
- `vector_feature`：`asset_version_id + geometry + properties JSONB`。
- `attachment_asset_version`：普通附件的 MIME、文件名等信息。
- `object_blob`：SHA-256、MinIO 对象键、大小、引用计数，用于物理去重。

分类方式不建独立数据表：

- 栅格、矢量、附件属于“物理类型”，使用扩展表。
- 上传、卫星采集、外部导入属于“来源”，使用来源字段。
- 生态、矿山、基础地理属于“业务分类”，使用目录和标签。

主键统一使用 UUIDv7；时间统一存 UTC。

核心 STAC 字段使用明确数据库列，扩展元数据使用 `properties JSONB`，并按资产模板通过 JSON Schema 校验。

## 上传与入库流程

1. FastAPI 创建 MinIO Multipart 上传会话。
2. 前端使用预签名 URL 直接上传分片，文件不经过 FastAPI。
3. 前端通知完成上传。
4. PostgreSQL 在一个事务中创建资产版本、Job 和 Outbox。
5. Dispatcher 将事件可靠投递 RabbitMQ。
6. Worker 流式计算 SHA-256，并进行物理对象去重。
7. 根据文件类型进入对应处理器。
8. 栅格生成原生 CRS 的 COG、缩略图、统计信息和 EPSG:4326 footprint。
9. 矢量保留原文件，同时将要素导入 PostGIS。
10. 普通附件只校验并存储。
11. 处理完成后更新为 `READY`，失败则保留诊断报告。

无法识别 CRS 或波段时进入 `NEEDS_INPUT`，用户补充信息后从中断步骤继续。不会擅自假定 EPSG:4326。

栅格默认样式自动识别 RGB/灰度波段；后续修改样式不重新生成 COG。

## Job 与调度

PostgreSQL 是任务状态权威来源，RabbitMQ 只负责传递消息。

Job 建议状态：

```
PENDING → QUEUED → RUNNING → SUCCEEDED
                     ├── RETRYING
                     ├── NEEDS_INPUT
                     ├── FAILED
                     └── CANCELLED
```

任务策略：

- 网络、MinIO 等瞬时错误自动指数退避。
- 文件损坏、参数错误等确定性错误不自动重试。
- 每类 Job 独立配置重试次数、超时和资源限制。
- Worker 所有步骤必须幂等。
- 前端首版轮询 Job；事件模型预留二期 SSE。
- Job 与 Outbox 同一事务提交，避免数据库成功但消息丢失。

监测计划支持固定间隔和 RFC 5545 RRULE。每次只处理上次成功执行后新增、空间相交且符合生态参数条件的资产，并保存不可变输入快照。停机后只补跑最近一次，其他周期标记为 `MISSED`。

## API 规范

统一使用 `/api/v1`：

- 成功响应直接返回资源。
- 分页统一为 `{items, total, page, page_size}`。
- 错误使用 RFC 9457 `application/problem+json`。
- 空间输入统一为 EPSG:4326 GeoJSON `Polygon/MultiPolygon`。
- 内部模型对齐 STAC 核心语义，首版不实现完整 STAC API。
- TiTiler 不直接暴露；API 签发短期瓦片令牌，由 Nginx 瓦片网关校验。
- MinIO 下载同样使用短期签名 URL。

首版移除 Excel/CSV 导出，只保留未来 Export Job 扩展位置。

## 首版业务范围

迁移：

- 数据资源目录。
- 卫星与传感器目录。
- 栅格、矢量、普通附件资产管理。
- 上传、版本、处理状态和成果管理。

- 矿山监测计划、增量匹配及执行快照。
- Job、Outbox、Scheduler、Worker、TiTiler。

不迁移：

- 若依用户、角色、菜单、部门和岗位。
- 登录、注册和验证码。
- 若依字典、配置、通知、监控和日志。
- Quartz、代码生成器、Druid。
- Excel/CSV 导出。
- 仓库中不存在的具体遥感算法。

## 鉴权预留

首版不实现登录，但现在保留：

- nullable `owner_id/created_by`。
- 统一 `ActorContext`。
- Service 层权限接入位置。
- 受控的瓦片和对象下载网关。

首版 `ActorContext` 返回匿名系统操作者。二期增加用户表、Argon2、JWT、`ADMIN/USER` 和“共享读、属主写”时，不需要改造 API 和任务主链路。
