# 旧接口→新用例迁移矩阵（Stage 0）

> 存放位置：本文档现位于 Python 实现仓库 `remote-scene-platform/doc/`。Java 参考仓库只读核对旧业务行为。
>
> 状态：Stage 0 建立，Stage 7 已完成静态逐行核对；Compose 全量验收状态见 README。
>
> 盘点范围：`ruoyi-multidata` 全部 9 个 Controller、`ruoyi-geo` 全部 1 个 Controller，共 55 个 HTTP 端点，外加 2 个仅 Service 层暴露的空间能力（`insertGeoDataEnvelope`、`selectIntersects`）。每个方法在本矩阵中恰好出现一次。
>
> 依据：Controller → Service → Mapper XML 完整调用链阅读；双数据源配置（master=MySQL，slave=PostgreSQL/PostGIS）；`ruoyi-admin/src/main/resources/application.yml`（`ruoyi.profile=C:/ruoyi/uploadPath`，multipart 10MB/20MB 限制）。

## 1. 分类定义

| 标记 | 含义 |
| --- | --- |
| `MIGRATED` | 能力按新 API 契约直接延续，语义基本一一对应 |
| `MERGED` | 与其他旧接口重复的能力，合并进统一新用例 |
| `REPLACED` | 用新机制重新达成同一业务目标，接口形态/实现机制发生变化 |
| `EXCLUDED_WITH_REASON` | 首版明确不做，必须给出理由 |

## 3. 不得复刻的已知缺陷清单

迁移时以下缺陷为已确认的真实行为，新系统必须避免：

1. **同步大文件处理**：分片合并、GDAL 重投影、PNG/缩略图生成全部阻塞在 HTTP 请求内，且被 DB 事务包裹（`mergeFile` @Transactional），大文件期间长期占用数据库连接。
2. **本地文件系统存储**：所有二进制落盘 `C:/ruoyi/uploadPath`，URL 依赖请求 Host 拼接（`ServerConfig.getDomain`）。
3. **自定义字符串协议**：`mapExtent = minX@!@minY@!@maxX@!@maxY`；`fileMerge` 响应 `缩略图URL$xiao&tif绝对路径$xiao&extent`；逗号分隔 id（`/{ids}`、`upload_data_ids`、`ecologicalCode`）。
4. **跨库双写无事务**：MySQL 业务行 + PostgreSQL `geo_data` 包络两段写，任一失败即不一致；`@Transactional("pgTransactionManager")` 引用不存在的 bean。
5. **重复入口/重复模型**：`SysUploadData` 与 `SysSatelliteData` 两套同构资产表；`SendTask` 与任务新增逐字重复；`TifTransformerUtils20250330` 整文件注释的死代码备份。
6. **静默失败**：tif 转换异常 `catch { e.printStackTrace() }` 吞掉返回半成功；空匹配集生成 `in ()` SQL 错误返回 500；树全环时静默返回扁平列表；`skipUpload=true` 时 url 恒为 null。
7. **非规范化关联**：目录树按 `parentCode == dataCode` 字符串弱关联；映射表按 code 软引用且允许改 code 不断链；`ORDER BY upload_data_ids` 对逗号串排序。
8. **校验缺失**：上传登记接口盲目信任客户端传入的服务器绝对路径；`ecologicalCode` null 即 NPE；`GET /multidata/file/list` 过滤条件被双重丢弃。
9. **伪调度**：`cycle` 字段仅存储、零消费，无任何调度实现。
10. **硬编码渲染**：RGB 波段固定 `{16,17,18}`，对普通 3 波段影像完全错误；tif 转换无 `-overwrite`，重复合并同名输出失败。
11. **路由/命名缺陷**：`/.multidata/uploaddata` 以点开头；权限串 `.multidata:uploaddata:*`；`SysSatelliteSensor` Mapper 接口与 XML 完全脱节（运行时不可用）；`getsatelliteCode()` JavaBean 命名不规范。
12. **权限空洞**：`POST /sendTask/minesatellitetask`、`POST /geo/gis`、`GET /geo/gis/area`、`GET /multidata/dataresource/multiDataResourcTree` 无权限注解。

| `sys_ecoparam_multidata_relationship` | MySQL | 生参-数源映射（双 code 列） | 改为显式多对多映射表 |
| `sys_mine_satellite_data_task` | MySQL | 矿山任务（boundary WKT、cycle、逗号 id 串） | 改为监测计划 + 执行 + 输入快照关联表 |
| `sys_chunk` / `sys_filelist` | MySQL | 分片与合并文件记录 | 由 MinIO Multipart 会话与 `object_blob` 取代，不迁移 |
| `geo_data` | PostgreSQL | 空间包络/要素（SRID 0） | 由版本 footprint（EPSG:4326）与 `vector_feature` 表取代 |

无生产数据需要迁移；仓库内 DDL 严重滞后（`sys_upload_data`、`geo_data` 等表 DDL 缺失，`sys_mine_satellite_data_task` 缺 `upload_data_ids` 列），新库结构以 `doc/总体架构.md` 数据模型为准，不从旧表反推。
